# Unity.Rea.QuickDuel

Two duelists face each other and wait. The moment comes. Whoever strikes first wins.

That's the whole game:

1. A "Get Ready" beat and a 3-2-1 countdown.
2. A standoff of unknown length (3 to 6.5 seconds).
3. The cue: the screen flashes and a blade is drawn.
4. Both players hit their key. The faster reaction wins.
5. Strike before the cue and you lose.

**Status: complete.** Every row of `docs/RECONSTRUCTION.md` is built or dropped on purpose, and the final play-through
(UQD-T54, evidence in `docs/parity`) is done: this is a finished proof of concept of Bushido Coda's reaction duel.

### The art pipeline

The original's sprites, sounds and fonts are not edited in Unity. In the editor, *QuickDuel > Import Original Assets*
(or `-executeMethod Unity.Rea.QuickDuel.EditorTools.OriginalAssetGenerator.Generate` in batch mode) copies them from the
GameMaker project, applies the import rules, builds the bitmap fonts and writes `Data/assets.json`. Scenes are built
the same way (*QuickDuel > Rebuild Duel / Intro / Main Menu Scene*); never hand-edit the scene YAML.

## Build and test

Open the folder in Unity 6000.4.3f1. Test the rules without the editor:

```
dotnet test Core.slnx
```

The rest of the tests run in Unity's Test Runner: EditMode (`Tests/Editor`: scene builders, art generators, settings
registry) and PlayMode (`Tests/PlayMode` and `Tests/Online`, including `ParitySceneTests`, which draws each scene and
checks it holds a real picture; set `QUICKDUEL_SHOTS` to save `parity-*.png`). A PlayMode run needs a graphics device;
set `QUICKDUEL_ALLOW_NO_GRAPHICS=1` to skip the drawn-scene tests on a machine without one. CI runs the Core suite on
every push and, when the Unity license secrets are set, the EditMode and PlayMode suites and the Windows build.

Build the Windows player to `Build/QuickDuel/QuickDuel.exe` (exits non-zero on failure):

```
powershell -File run.ps1
```

Launch a playable build for development (builds it first if `Build/QuickDuel/QuickDuel.exe` is missing;
`-Build` rebuilds, `-Wait` waits for it to exit, the log goes to `Logs/play.log`):

```
powershell -File play.ps1
```

### Muted launches

`play.ps1` launches muted: it sets `MINDATTIC_CLI_MUTED=1` and passes `-muted`, so a CLI or agent starting
the game never blasts audio. Pass `-Sound` to launch with audio. Either switch works on its own when you
start `QuickDuel.exe` (or the editor) yourself:

```
$env:MINDATTIC_CLI_MUTED = '1'; .\Build\QuickDuel\QuickDuel.exe
.\Build\QuickDuel\QuickDuel.exe -muted
```

The mute is the shared `com.mindattic.unity.shared` session mute: read before the first scene loads, it
makes the player profile's settings report sound muted for that run only, and `SessionAudio` silences the
listener. The player's saved `settings.json` is never written, so the next normal launch has sound. A
profile whose own settings mute sound effects is honoured the same way; otherwise the game plays at the profile's
sound-effect volume, the one a player keeps across every MindAttic game. The `-batchmode` runs in
`run.ps1` and the tests play nothing audible and don't need it.

## Controls

The game opens on the intro (click, key or pad button skips it), then the main menu: New Game (vs computer), Versus
(two players), Credits and Quit, with the computer's difficulty in the Options slot. Mouse, arrows or d-pad and Enter
drive it.

In a duel: each round's countdown begins by itself 3 s after the loading image clears, as the original's startup did;
a click (or a gamepad's south button) begins it at once. The original's keys strike: against the computer Space or the
left mouse button (or touch); in Versus Left Ctrl for the left fighter and Right Ctrl for the right. Gamepad 1's south
button strikes for the left fighter and gamepad 2's for the right. The mode (Versus, or the computer at Easy, Normal or
Hard, playing the right side) is chosen on the main menu. A match is best of 3, then Retry or Continue. Everywhere: F1 toggles fullscreen (the 640 x
480 frame letterboxes into any window). In the duel, Escape, or gamepad Select held while pressing Start, leaves for the
main menu at any moment (not under the victory or game over screen); on the main menu Escape quits the player. F12 shows the debug overlay in the editor and development builds.

Rounds are judged by input event timestamps, not by frame, so the frame rate can't decide a duel.
